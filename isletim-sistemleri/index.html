Bölüm 1

Konu özeti

HAFTA 1İşletim sistemine giriş

  • İS: donanımı yöneten, kullanıcı ile donanım arasında aracı program. Sürekli çalışan kısmı kernel. Mobil İS'lerde ayrıca middleware var.
  • Sistem 4 bileşen: donanım, İS, uygulama programları, kullanıcılar.
  • Bootstrap (firmware) ROM/EEPROM'da; kernel'i belleğe yükler. UNIX'te ilk process init.
  • Olaylar interrupt ile bildirilir: donanım sinyal ile, yazılım system call ile. Yazılım kesmesi = trap/exception. Interrupt adresleri interrupt vector tablosunda.
  • Depolama hiyerarşisi: yukarı çıktıkça hız ve maliyet artar, kapasite azalır. Register/cache/RAM volatile, disk nonvolatile.
  • DMA: blok veri cihaz ile bellek arasında doğrudan aktarılır, CPU o sırada başka iş yapar.
  • Çok işlemcili sistemin 3 avantajı: throughput, ekonomik ölçek, güvenilirlik (graceful degradation). AMP: her işlemciye bir iş, biri yönetir. SMP: tüm işlemciler eş düzey, her işi yapabilir. UMA/NUMA.
  • Clustered sistemler: LAN üzerinden, loosely coupled, high-availability. Asimetrik: hot-standby.
  • Multiprogramming: birden çok işi aynı anda bellekte tutar, CPU'yu boş bırakmaz. Multitasking (time sharing): beklemesiz hızlı geçiş.
  • Dual mode: mode bit, user = 1, kernel = 0. Boot'ta kernel mode. Timer: sonsuz döngüde kontrolü İS'e geri alır.
  • Process yönetimi görevleri: oluşturma/silme, askıya alma/devam ettirme, senkronizasyon, haberleşme. Program pasif, process aktif.
  • Protection: kaynağa erişimin denetlenmesi. Security: iç/dış saldırılara karşı koruma.
  • Kernel veri yapıları: stack LIFO, queue FIFO, BST O(n), dengeli BST O(log n), hash O(1), bitmap.
  • Bulut: SaaS (Word, Excel), PaaS (veritabanı), IaaS (sunucu, depolama). Açık kaynak: Linux. Mac OS X hibrit (Darwin).

HAFTA 2İşletim sistemi yapıları

  • Kullanıcı arayüzleri: CLI (shell), batch, GUI. İlk GUI Xerox Alto (1973).
  • System call: servisler için arayüz. Programcı API kullanır (Windows API, POSIX, Java). Parametre geçirme 3 yolla: register, bellekte blok/tablo, stack.
  • 6 sistem çağrı türü: process control, file management, device management, information maintenance, communications, protection.
  • Haberleşme modelleri: message passing ve shared memory.
  • MS-DOS: single-tasking, basit yapı, uygulamalar donanıma doğrudan erişebilir (risk). FreeBSD: multitasking.
  • Policy ne yapılacağını, mechanism nasıl yapılacağını belirler (timer = mekanizma, süre kararı = kural).
  • Yapılar: basit (MS-DOS), katmanlı (alt katmanın hizmetini kullanır, debug kolay, performans düşebilir), mikrokernel (Mach; çekirdekte sadece temel işlevler, mesajlaşma, daha güvenli), modül (yüklenebilir kernel modülleri, en iyi yaklaşım), hibrit (Windows, Mac OS X, Linux).
  • Android: Linux kernel + Dalvik VM. iOS: Cocoa Touch, Core OS.
  • Kernel hatası = crash. Hata analizi: log + memory dump. Performance tuning.
  • Boot: bootstrap ROM'da kernel'i yükler; boot kısmı olan disk = boot disk/system disk.

HAFTA 3Process yönetimi

  • Process bellek bölümleri: stack (parametre, dönüş adresi, yerel değişken), data (global), heap (dinamik), text (kod).
  • Durumlar: New, Ready, Running, Waiting, Terminated. Ready = CPU bekler, Waiting = olay/I/O bekler.
  • PCB: state, program counter, CPU register'ları, scheduling (öncelik), memory (base/limit), accounting (pid), I/O durumu.
  • Kuyruklar: job queue (tüm işler), ready queue (bellekte, CPU bekleyen), wait/device queue. Linked list ile tutulur.
  • Scheduler: long-term (job, dakikalar), short-term (CPU, <100 ms), medium-term (swapping). Windows/Unix'te long-term yok.
  • I/O-bound vs CPU-bound. Hepsi I/O-bound ise ready queue boş, hepsi CPU-bound ise I/O kuyruğu boş.
  • Context switch: CPU'nun process değiştirmesi; bağlam PCB'de saklanır, sık yapılırsa overhead.
  • Process oluşturma: parent/child, pid; UNIX'te fork(), exec(), wait(); sonlandırma exit(). Windows'ta CreateProcess(), TerminateProcess().
  • Independent (etkilenmez) vs cooperating (veri paylaşır). İşbirliği nedenleri: information sharing, computation speedup, modularity, convenience.
  • IPC: shared memory (daha hızlı; producer buffer'a yazar, consumer okur) ve message passing (send/receive, dağıtık ortam).
  • Soket = IP + port. HTTP 80, FTP 21, 127.0.0.1 loopback. TCP güvenilir (Socket), UDP bağlantısız (DatagramSocket).

HAFTA 4Thread'ler

  • Thread'in kendine ait: PC, register kümesi, stack. Paylaşılan: kod, data, dosyalar.
  • 4 fayda: responsiveness, resource sharing, economy, scalability. Solaris: thread oluşturma 30x, context switch 5x hızlı.
  • Concurrency: tek core'da dönüşümlü ilerleme. Parallelism: gerçekten aynı anda çalışma.
  • Amdahl: hızlanma ≤ 1 / (S + (1−S)/N). S = 0,25 → N=2: 1,6x; N=4: 2,28x; N→∞: 1/S. Seri oran artınca maksimum hızlanma düşer.
  • 5 zorluk: identifying tasks, balance, data splitting, data dependency, testing/debugging.
  • Data parallelism (verinin parçaları core'lara) vs task parallelism (görevler core'lara).
  • Modeller: many-to-one (tek kernel thread; biri bloklanırsa process bloklanır, paralel yok), one-to-one (Linux, Windows; her user thread için kernel thread), many-to-many (Solaris 9).
  • Kütüphaneler: Pthreads (user veya kernel), Windows (kernel), Java (user, JVM). Asenkron vs senkron (fork-join).
  • Implicit threading: thread'leri compiler oluşturur. Thread pool, OpenMP (#pragma omp parallel), GCD (^ blok).
  • Sinyal: senkron (0'a bölme, illegal bellek), asenkron (Ctrl+C). İptal: asenkron (aniden) ve deferred (kendi kendini).
  • Windows: ETHREAD, KTHREAD, TEB. Linux: clone() ile paylaşım bayraklı görev.
Bölüm 2

Olası sınav senaryosu

20 soruluk örnek set şıklı sorulardan oluşuyor ve sorular haftalara eşit dağılmış. Kapsam 4 slayt olduğuna göre senkronizasyon soruları (setin son 5 sorusu) yerine thread ve process sorularının artması bekleniyor. Tahmini dağılım:

Kesin çalışılması gerekenler (hem quizde hem örnek sorularda)

  1. Process durumları: Ready ile Waiting farkı, "kilitli" diye bir durum yok.
  2. Multiprogramming amacı: CPU kullanımını artırmak / birden fazla işi bellekte tutmak.
  3. Thread avantajları: paralel/eşzamanlı çalışma, kaynak paylaşımı; thread'ler kod ve veriyi paylaşır, stack ve PC paylaşmaz.
  4. Thread modelleri: many-to-one'da tek kernel thread var; one-to-one'da her user thread'e bir kernel thread.
  5. User-level ve kernel-level thread: user-level bloklanınca tüm process bloklanır, kernel-level multicore'da paralel çalışır.
  6. PCB ve Program Counter: PCB'de kullanıcı adı yok; PC sonraki komutun adresini tutar.
  7. İS mimarileri: katmanlı (bitişik katmanlar, düzenli yapı), mikrokernel (sadece temel işlevler), modüler (sonradan bileşen ekleme).
  8. MS-DOS: single-tasking, thread desteği yok, donanıma doğrudan erişim riski.
  9. SMP: tüm işlemciler eş düzey ve her işi yapabilir.
  10. Kernel, system call ve kernel mode: sistem çağrısı yazılım kesmesidir; açılış kernel mode'da olur.

Dikkat: Hoca 1. quizde multiprogramming için "aynı anda birden fazla işi bellekte tutmak" şıkkını doğru saydı, 3. quizde ve örnek sorularda ise "CPU kullanımını artırmak" doğru. İkisi de slaytta geçiyor. Şıklarda ikisi birlikte varsa soru köküne bak: "amaç" deniyorsa CPU kullanımı, "nasıl çalışır / ne yapar" deniyorsa bellekte birden fazla iş.
