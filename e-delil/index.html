1 · Regex (düzenli ifade) ve grep

Adli bilişimde elimizde dev metin/log dosyaları olur. İçinden IP, e-posta, telefon, MAC adresi gibi delilleri kalıp (pattern) ile bulmak için regex kullanırız.

Regex nedir? (tanım sorusu gelebilir)Düzenli ifade (Regular Expression), bir arama veya eşleşme kalıbını tanımlayan özel bir karakter dizisidir. Metinlerden bilgi ayıklamak için kullanılır: kaynak kodlar, log dosyaları, Word/Excel/PowerPoint belgeleri (önce sıkıştırılmış yapıları açılmalı), ikili (binary) veriler. Genellikle grep gibi komut satırı araçlarıyla kullanılır.

1.2 grep komutu ve seçenekleri

grep = dosyada/metinde kalıp arayan Linux komutu. Bulduğu satırın tamamını yazar (aksi söylenmedikçe).

grep [SEÇENEKLER] "KALIP" dosya
komut | grep [SEÇENEKLER] "KALIP"     # | (pipe): soldaki komutun çıktısını grep'e verir
SeçenekAnlamı
-EExtended regex (+ ? | {} () doğrudan çalışsın). Hep kullan.
-oOnly matching: satırın tamamı değil, sadece eşleşen kısım
-iBüyük/küçük harf duyarsız
-nSatır numarasını göster
-cEşleşen satır sayısını ver
-vEşleşmeyen satırları göster (tersi)
-wSadece tam kelime eşleşsin
-rKlasörde alt klasörlerle birlikte ara
-A n / -B n / -C nEşleşmeden sonraki (After) / önceki (Before) / iki yandaki n satırı da göster
-PPerl uyumlu regex. Lookahead/lookbehind ve koşullu ifade için gerekli
--colorEşleşeni renkli göster
echo "This is Frank Xu" | grep -Ei "frank"          # -i sayesinde Frank bulunur
echo "This is Frank Xu" | grep -E "(F|f)rank"        # F veya f
echo "I am Frank Xu" | grep -Eo "\b[A-Z][a-z]{1,10}\s+[A-Z][a-z]{1,10}\b"   # çıktı: Frank Xu
echo "pretend fishing working" | grep -Po "(?<=pre)\w+"   # çıktı: tend
echo "fishing working enjoying" | grep -Po "\w+(?=ing)"  # çıktı: fish work enjoy
grep -Ec "public" Hello.java                        # kaç satırda geçiyor
grep -En "String" Hello.java                        # satır numarasıyla
grep -Eo "kelime" dosya | wc -l                     # kaç KEZ geçiyor (her eşleşme ayrı satır)
grep -Eo "KALIP" dosya | sort | uniq -c             # tekrarsız liste + kaç kez
İsim kalıbını parça parça okuma (sınavda böyle açıkla) \b[A-Z][a-z]{1,10}\s+[A-Z][a-z]{1,10}\b
\b kelime başı · [A-Z] bir büyük harf (adın ilk harfi) · [a-z]{1,10} 1–10 küçük harf · \s+ bir veya daha fazla boşluk · [A-Z][a-z]{1,10} soyadı · \b kelime sonu.

1.4 Farklı dosyaların içinde arama

a) Word (.docx) içinden e-posta bulmak

.docx aslında sıkıştırılmış (zip) bir dosyadır. İçindeki metin word/document.xml dosyasındadır. Doğrudan grep yaparsan bir şey bulamazsın ya da XML etiketleriyle dolu çıktı alırsın.

unzip customers.docx -d customers                 # 1) zip'i klasöre aç
grep "ubalt.edu" customers/word/document.xml      # 2) bulur ama çıktı XML etiketleriyle dolu
sed 's/<[^>]*>/ /g' customers/word/document.xml \
  | grep -Eo "[a-zA-Z0-9.-]+@[a-zA-Z0-9]+\.[a-z]{2,4}"   # 3) etiketleri sil, sonra mailleri çek
sed nedir?Stream Editor. Metni satır satır okuyup arama, değiştirme ve silme yapar. Yazım: sed 's/ARANAN/YENİ/g' (s = substitute, g = satırdaki hepsi).
echo "123-456-7890" | sed 's/1/4/g' → 423-456-7890
echo "123-456-7890" | sed 's/-//g' → 1234567890 (tireleri sil)
echo "123-456-7890" | sed 's/-/./g' → 123.456.7890
echo "<h1>Başlık</h1>" | sed 's/<[^>]*>//g' → Başlık. [^>]* = "> olmayan karakterler", böylece her etiket ayrı ayrı silinir.

b) pcap (ağ trafiği) içinden MAC adresi bulmak

pcap ikili (binary) dosyadır; önce tshark ile metne çevrilir, sonra grep.

tshark -r arp.pcap                                  # -r: okunacak dosya
tshark -r arp.pcap -T fields -e eth.src -e eth.dst  # -T fields + -e: sadece istenen alanlar
tshark -r arp.pcap -T fields -e eth.src | grep -Eo "([0-9a-f]{2}:){5}[0-9a-f]{2}" | sort -u

c) iOS plist içinden tarih bulmak (örnek sınavdaki soru tipi)

Soru: "com.burbn.threads.plist dosyasından şu çıktıyı veren Linux komutunu yazınız:"

<key>ds-app-install-date</key>
<date>2020-04-13T19:30:04Z</date>
grep -A1 "ds-app-install-date" com.burbn.threads.plist
# "ds-app-install-date" geçen satırı bul, -A1 ile ALTINDAKİ 1 satırı (tarih) da göster
Bu soru tipinin mantığıÇıktıda 2 satır var ve ikincisi aranan kelimeyi içermiyor → -A 1 gerekli. Çıktıya bakıp "hangi kelime aranmış, kaç satır gösterilmiş" diye düşün. Yorum: uygulamanın kurulum tarihi 13.04.2020 19:30:04 UTC (Z = UTC). Şüphelinin "yüklü değildi" iddiası çürür.

İlişki (sınavda "URL ve visit tablosu arası ilişki" diye sorulur)

visits.url→ eşittir →urls.id   |   visits.from_visit→ eşittir →visits.id (önceki ziyaret)

Bir URL'ye birden çok ziyaret olabilir: urls → visits ilişkisi bire-çok. URL adresini, sayfa başlığını ve erişim zamanını birlikte görmek için iki tablo JOIN ile birleştirilir:

select v.id, u.url, u.title,
       datetime(v.visit_time/1000000 + strftime('%s','1601-01-01'), 'unixepoch','localtime') as zaman,
       v.from_visit, v.transition & 0xFF as tip, v.visit_duration/1000000.0 as sure_sn
from visits v join urls u on v.url = u.id
order by v.visit_time;

Örnek: google.com'dayken bir linke tıklayıp cnn.com'a gittin. urls'de cnn.com bir kayıt (ör. id=2). visits'te yeni satır: url=2, from_visit = google ziyaretinin id'si, transition = 0 (Link).

2.3 WebKit nedir ve zaman dönüşümü

WebKit nedir? (örnek sınavda soruldu, listede de var) WebKit, web tarayıcılarının HTML, CSS, JavaScript ve görsel öğeleri işleyip ekranda düzenli bir web sayfası olarak göstermesini sağlayan açık kaynaklı tarayıcı motorudur (tarayıcının "kalbi"). Safari'nin motorudur; Chrome ve Opera'nın motoru Blink de WebKit'ten türemiştir.
Görevleri: HTML'i işler (yapı, içerik) · CSS'i uygular (renk, font, yerleşim) · JavaScript'i yürütür (etkileşim) · farklı platformlarda çalışır.
Avantajları: hızlı, düşük kaynak kullanımı, açık kaynak, mobil uyumlu, web standartlarına uygun, kolay güncellenir.
Benzetme: HTML evin planı, CSS iç mimarın dekorasyonu, JavaScript elektrik/otomasyon sistemi; WebKit bunları alıp evi inşa eden ekip.
Adli bilişimdeki önemi: Chrome/Safari geçmişindeki zamanlar WebKit zaman damgası biçimindedir.
Başlangıç noktası (epoch)Birimi
WebKit / Chrome zamanı1 Ocak 1601 00:00 UTC (Windows NT FILETIME ile aynı)mikrosaniye (saniyenin milyonda biri), 64 bit
Unix / Epoch zamanı1 Ocak 1970 00:00 UTCsaniye
Ezberle: dönüşüm formülü İki başlangıç arasındaki fark = 369 yıl = 11 644 473 600 saniye.
Unix (sn) = WebKit / 1 000 000 − 11 644 473 600
SQL'de: strftime('%s','1601-01-01') = 1601'in Unix karşılığı = −11644473600. Yani visit_time/1000000 + strftime('%s','1601-01-01') aynı çıkarmayı yapar.

2.5 Transition (geçiş) kodunu hesaplamak

Transition, kullanıcının sayfaya nasıl ulaştığını söyler (linke tıkladı, URL'yi yazdı, form gönderdi…). 32 bitlik bir sayıdır:

Üst 24 bit = qualifier (ek bilgi bayrakları)+Alt 8 bit = çekirdek tip (0–10)

Hesaplama adımları (hocanın yöntemi)

  1. Decimal → Hexadecimal çevir.
  2. Sonucu 0xFF ile AND'le (= son iki hex rakamını al). Bu çekirdek tiptir.
  3. Değeri transition tablosundan bak ve yorumla.
  4. (Ekstra) Kalan üst kısım (sayı & 0xFFFFFF00) → qualifier tablosundan yorumla.
printf '%X\n' 805306375          # → 30000007  (hex)
echo $((805306375 & 0xFF))       # → 7        ($(( )) bash'te aritmetik işlem yapar)
echo $((0x30000007 & 0xFF))      # → 7

Elle hesap (hesap makinesi yoksa): sürekli 16'ya böl

805306375 → hex:

805306375 / 16 = 50331648  kalan 7
 50331648 / 16 =  3145728  kalan 0
  3145728 / 16 =   196608  kalan 0
   196608 / 16 =    12288  kalan 0
    12288 / 16 =      768  kalan 0
      768 / 16 =       48  kalan 0
       48 / 16 =        3  kalan 0
        3 / 16 =        0  kalan 3
Kalanları aşağıdan yukarı oku → 0x30000007

AND işlemi: 0x30000007 & 0x000000FF = 0x00000007 → 7 = Form Submit.

Kalan: 0x30000000 = 0x10000000 + 0x20000000 → Chain Start + Chain End (tek adımlık, kendi başına bir gezinti zinciri).

Kestirme0xFF ile AND = sayının 256'ya bölümünden kalan (pozitif sayılar için). 805306375 mod 256 = 7. Çünkü 0x30000000 = 805306368 tam 256'nın katıdır. Hızlı kontrol için çok işe yarar.

3.4 Conversion: Base64

Base64 nedir?İkili (binary) veriyi (resim, ses, dosya) sadece yazdırılabilir ASCII karakterlerine (A–Z, a–z, 0–9, +, /, dolgu için =) dönüştüren bir kodlama şemasıdır. Amaç: veriyi e-posta, URL, JSON, XML gibi metin tabanlı ortamlarda bozulmadan taşımak.
Dikkat: Base64 şifreleme değildir; anahtar gerektirmez, herkes geri çevirebilir. SMTP AUTH'ta şifrenin Base64 olması güvenlik sağlamaz.

Elle nasıl çevrilir? (3 bayt → 4 karakter)

  1. Metni ASCII → 8 bitlik ikiliye çevir.
  2. Bitleri 6'şarlı gruplara böl (3 bayt = 24 bit = 4 × 6 bit).
  3. Her 6 bitlik değeri (0–63) tablodan karaktere çevir: 0–25 → A–Z, 26–51 → a–z, 52–61 → 0–9, 62 → +, 63 → /.
  4. Son grupta eksik bayt varsa sona = (1 eksik) ya da == (2 eksik) eklenir.

4.1 TCP üçlü el sıkışma ve SYN Flood

İstemci → SYN (seq=m)→Sunucu → SYN+ACK (seq=n, ack=m+1)→İstemci → ACK (ack=n+1)→ESTABLISHED

Durumlar: istemci CLOSED → SYN-SENT → ESTABLISHED; sunucu LISTEN → SYN-RECEIVED → ESTABLISHED. Sequence #: gönderilen ilk baytın numarası (rastgele ya da 0'dan başlar). ACK #: alıcının beklediği bir sonraki bayt numarası (SYN için +1).

HTTP SYN Flood nedir? (örnek sınavda soruldu)Saldırgan, hedef sunucuya (ör. web sunucusu port 80) çok sayıda SYN paketi gönderir ama el sıkışmayı tamamlamaz (son ACK'yı göndermez). Sunucu her yarım bağlantı için SYN+ACK gönderip kaynak ayırarak bekler. Yarım açık bağlantılar kuyruğu doldurur, sunucu meşru kullanıcılara hizmet veremez. Bu bir DoS/DDoS saldırısıdır. Kaynak IP sahte (spoofed) olabilir.
Wireshark'ta delil: kaynaktan sürekli SYN geliyor, karşılığında el sıkışma tamamlanmıyor; kaynak portlar rastgele.
hping3 -S --flood -V -p 80 192.168.78.11               # -S: SYN bayrağı, --flood: olabildiğince hızlı, -p: hedef port
hping3 -S --flood -V -d 6000 -p 80 192.168.78.11       # -d: veri boyutu 6000 bayt (MTU 1500 → paket parçalanır)
hping3 -S --flood -V -a 15.15.15.15 -p 80 192.168.78.11 # -a: sahte kaynak IP

Scapy ile: IP(dst=hedef)/TCP(sport=RandShort(), dport=80, flags="S")/Raw(b"X"*boyut) ve send(p, count=n, verbose=0). Veri boyutu verilmezse 20 bayt TCP + 34 bayt başlık = 54 baytlık çerçeve. MTU: Ethernet'te 1500 bayt; IP+TCP başlıkları çıkınca ~1460–1480 bayt veri; daha büyük veri parçalanır (DF/MF bitleri).

4.2 ARP ve ARP Poisoning

ARP (Address Resolution Protocol): yerel ağda IP adresini MAC adresine eşler. Cihazlar diğerlerinin IP'sini bilir ama veri göndermek için MAC lazım. A cihazı "bu IP kimin?" diye broadcast (ff:ff:ff:ff:ff:ff) ARP request atar, sahibi ARP reply ile MAC'ini söyler. Eşlemeler ARP tablosunda (ARP cache) tutulur; her cihazın kendi tablosu vardır, dinamiktir, süresi dolar. arp -a / ip neigh ile görülür; ping de ARP kullanır.

ARP Spoofing / Poisoning nedir?Saldırgan LAN'a sahte ARP cevapları gönderir: kurbana "gateway'in IP'si bende, benim MAC'imi kullan", gateway'e "kurbanın IP'si bende" der. İki tarafın ARP tablosu zehirlenir ve trafik saldırgan üzerinden akar → Man-in-the-Middle (MITM): dinleme, değiştirme, bilgi çalma, ağ kesintisi.
Spoofing = başkasının kimliğini (IP) kullanmak; poisoning = bunun sonucu (zehirlenmiş tablo).
Önlem: ARP spoofing tespit yazılımı, cihaz sayısını sınırlamak, VLAN, statik ARP.
Delil: Kurbanın ARP tablosunda gateway IP'si saldırganın MAC'iyle görünür; Wireshark'ta aynı MAC'ten çok sayıda istenmemiş ARP reply ("duplicate use of IP" uyarısı).

4.3 DHCP Starvation

DHCP, cihazlara otomatik IP, ağ geçidi ve DNS verir (havuzdan). Lab'daki router ayarı: ip dhcp pool, network 192.168.26.0 255.255.255.0, default-router, dns-server 8.8.8.8, ip dhcp excluded-address (dağıtılmayacak adresler), ip helper-address (DHCP isteğini başka ağdaki sunucuya ilet).

DHCP Starvation nedir?Saldırgan, sahte MAC adresleriyle binlerce DHCP DISCOVER/REQUEST gönderip havuzdaki tüm IP adreslerini tüketir. Gerçek kullanıcılar IP alamaz (DoS). Çoğunlukla ardından saldırgan kendi sahte (rogue) DHCP sunucusunu kurup kendini gateway/DNS olarak dağıtır → MITM. Delil: router'da show ip dhcp binding tablosu birbirine benzemeyen, anlamsız MAC'lerle dolu.

4.4 Taciz e-postası incelemesi (Nitroba senaryosu)

Kimya öğretmeni Lily Tuckrige taciz e-postaları alıyor. Mail başlığı yurt odası IP'sini (140.247.62.34) gösteriyor; odada 3 kişi ve şifresiz Wi-Fi router var → IP tek başına kişiyi göstermez. Ağa sniffer konuyor; ikinci mail willselfdestruct.com üzerinden gönderiliyor.

  1. Siteye kim girdi? Sayfa başlığında "WillSelfDestruct" ara → site IP 69.25.94.22, şüpheli 192.168.15.4.
  2. Taciz içeriğini POST etti mi? http.request.method == "POST" → içerik bulundu.
  3. IP birden çok kişide olabilir → MAC adresi (benzersiz): 00:17:f2:e2:c0:ce (Apple cihaz).
  4. MAC'i kişiye bağlama: HTTP durumsuzdur (stateless), sunucu kullanıcıyı cookie ile hatırlar. Cookie'lerde e-posta/kullanıcı adı aranır → sınıf listesindeki öğrenciyle eşleştirilir.
  5. Zaman: Wireshark zaman formatını değiştir.
